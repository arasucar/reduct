# Application agents and Reduct

Follow the application's existing instructions. Read `.reduct/agent/README.md` for roles, selective context access, authority, and editing safeguards. Reading it does not switch you to the planning role used by agents started in `.reduct/`.

Start with `reduct context ID --current` and retrieve applicable constraints, relevant Feature sections, and task-relevant open discussions. Load investigation and delivery history only when needed. For a manual handoff, follow the exact supplied brief/version and reconcile material source conflicts. Retrieve `guide completion` before planned implementation or completing Work; use `guide mapping` for first setup.

Clarify essential behavior, choose routine details within scope, and implement the owner's authorized request. Ask only about material scope, essential behavior, data protection, or costly commitments. Continue independent scope while unrelated decisions remain open; refine reversible details through owner testing and targeted adjustments.

Works belong under Modules and link affected Features. Features describe delivered behavior; active Works describe intended changes. Missing Feature documentation does not block implementation, and small direct repairs need no ceremonial Work or brief. After delivery, update affected current statements and record concise actual verification with evidence references. Preserve detailed history on demand. Keep the problem, desired result, current status, and next action easy to find; documentation maintenance should remain proportional to the change.

## Bugs

Create a `bug` under its owning Feature, never under a Module. Keep all bug information in that single document: report, expected and actual behavior, reproduction evidence, investigation, fix plan, decisions, progress, implementation outcome, and verification. Do not create a separate Work, Analysis, implementation brief, or bug document for the same bug. Add sections only when needed. Use `update-bug` for status and `complete` with actual verification and affected-Feature acknowledgements. Bugs use red styling, support comments and retained versions, and follow the closed-record history toggle. Ordinary Works still belong to Modules.

Automatic retention reuses unchanged document text. Do not request a snapshot for every edit or status update; use explicit checkpoints only when the owner requests one or a meaningful handoff needs an exact version. Review submission saves one version; History groups duplicate text without deleting existing evidence.

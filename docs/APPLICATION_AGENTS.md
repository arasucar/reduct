# Application agents and Reduct

Follow the application's existing instructions. Read the compact `.reduct/agent/README.md` for responsibilities, boundaries, and efficient record access. Retrieve deeper procedures with `reduct guide TOPIC` or `.reduct/agent/reference/README.md` when needed; use `guide completion` before planned implementation or completing Work, and `guide mapping` for first setup.

For direct application requests, inspect relevant `.reduct/modules/` feature records and sources. For planned implementation, read the owner's supplied brief or saved version, its Work, affected features, and source context. Reading workflow documentation does not switch you to the planning role used by agents started in `.reduct/`.

Work belongs directly to a Module and links affected Features. Missing Feature documentation does not block starting authorized implementation; create or update Feature records to describe delivered behavior and link them to the Work. Choose routine technical details within scope, proceed on independent agreed scope while unrelated decisions remain open, and refine reversible details through owner testing and targeted adjustments. Ask only about material scope or essential behavior changes, data protection, or costly commitments.

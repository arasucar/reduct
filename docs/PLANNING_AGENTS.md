# Reduct planning agents

An agent started in this directory is a planning and documentation agent. Follow the application's parent instructions. Read `agent/README.md`: its Agent roles section defines responsibilities and limits, Initial product mapping covers first setup, and Agent workflow defines records and CLI procedures.

Resolve requests by stable record ID, Markdown path, or title. Read the target, parents, linked features, supporting documents, and open reviews. For staged workspaces use `source_repository` to find the application. Re-read current hashes before edits and report record paths, unresolved decisions, and evidence limits.

## Document formatting

Keep new and revised product documents simple and easy to comment on. Use plain paragraphs, ATX headings (`#`, `##`, `###`), flat bullet or numbered lists, occasional bold emphasis, single-line inline code, and ordinary Markdown links. Use LF line endings and spaces instead of tabs. Keep inline formatting within one line.

Prefer prose and short lists. Avoid blockquotes, nested lists, tables, task checkboxes, HTML, images, diagrams, and decorative formatting. If a code example is necessary, use a fenced block starting at column one, with spaces for indentation; keep it outside lists and blockquotes. Keep source references in a separate section.

Preserve required record headings, YAML frontmatter, stable IDs, and evidence. Apply these conventions to current drafts; do not reformat retained versions, rewrite discussion history, or alter exact owner quotations. See Document formatting in `agent/README.md` for the shared convention.
